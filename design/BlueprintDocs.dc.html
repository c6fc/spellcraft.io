Concepts / Native functions

Native functions

Native functions are the seam between Jsonnet and JavaScript. They are what let a manifest ask your cloud provider a question while it is being evaluated, instead of being handed an answer someone pasted in.

Exporting a function

Every export from a plugin’s main other than _spellcraft_metadata becomes a native function. Export it bare, or as an array naming its parameters:

module.js
exports.resourceName = [function (name) {
  return `${this.environment}-${name}`;
}, 'name'];

The array form states the parameter names outright. Prefer it: the bare form recovers names by reading the function’s own source, which cannot work on minified or destructured parameters.

Namespacing

Functions register as <package-name>:<export>, so two plugins can both export client without colliding. Your module.libsonnet must use the fully qualified name:

module.libsonnet
resourceName(name):: std.native("@you/your-plugin:resourceName")(name),
Arguments must be primitives
Jsonnet will not pass an object or an array into a native function — it raises “native extensions can only take primitives”. Serialise with std.manifestJsonEx and parse inside the function. Return values have no such restriction.

Memoisation

Results are cached per (name, arguments) for the life of a render. Calling getCallerIdentity() in forty places costs one API call, and a timestamp taken twice agrees with itself.

This also means side effects fire once. If you need a function to run again with the same arguments, that is a signal it should be an init hook instead.
