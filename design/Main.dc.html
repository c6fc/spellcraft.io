Infrastructure orchestration

Configuration that knows where it’s running.

SpellCraft evaluates Jsonnet with live cloud APIs in reach, then emits plain Terraform JSON. Account IDs, existing buckets and enabled services get discovered — not pasted in.

It doesn’t replace Terraform and owns no state of its own. Delete it tomorrow and your infrastructure is still there.

Get started Read the docs
manifest.jsonnet → main.tf.json 
// Runs at evaluation time, against your real account.
local aws = import "@c6fc/spellcraft-aws-auth/module.libsonnet";
local s3  = import "@c6fc/spellcraft-aws-s3/module.libsonnet";

local account = aws.getCallerIdentity().Account;

{
  "main.tf.json": {
    resource: s3.bucket("artifacts-%s" % account, {
      versioned: true,
    }),
  },
}
01

Why not just write more Terraform modules?

Modules don’t resolve dependencies

A module can’t declare that it needs another module at a version. SpellCraft plugins are ordinary npm packages, so npm install does exactly what it already does everywhere else in your stack.

There is no runtime before apply

Enabling the API a resource depends on has to happen first. Plugins coordinate on lifecycle events, so the bootstrap runs itself instead of living in a README as step zero.

HCL can’t reach out

count and for_each are not a programming language. Jsonnet composes properly, and native functions call real APIs while the config is being evaluated.
