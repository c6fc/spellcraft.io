Config that reads the room.

SpellCraft evaluates Jsonnet with live cloud APIs in reach, then emits plain Terraform JSON. Account IDs, existing buckets, enabled services — discovered at render time, not pasted in.

No new state model. No control plane. Delete SpellCraft tomorrow and you still have your infrastructure.

get started
$ npm init spellcraft my-infra
manifest.jsonnet 
// evaluated against your real account
local aws = import "@c6fc/spellcraft-aws-auth/module.libsonnet";
local s3  = import "@c6fc/spellcraft-aws-s3/module.libsonnet";

local account = aws.getCallerIdentity().Account;

{
  "main.tf.json": {
    resource: s3.bucket("artifacts-%s" % account, {
      versioned: true,
    }),
  },
}
// render/main.tf.json
{
  "resource": {
    "aws_s3_bucket": {
      "artifacts-4419...": {
        "bucket": "artifacts-4419..."
      }
    }
  }
}

Why not just more Terraform modules?

Three things a module cannot do, no matter how it is written.

[01]

no dependency resolution

A module can’t declare it needs another module at a version. Plugins are npm packages, so npm install does what it already does everywhere else in your stack.

[02]

no runtime before apply

Enabling the API a resource needs has to happen first. Plugins coordinate on lifecycle events, so the bootstrap runs itself instead of living in a README as step zero.

[03]

HCL can’t reach out

count and for_each are not a programming language. Jsonnet composes, and native functions call real APIs mid-evaluation.
