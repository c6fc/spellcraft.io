Rendering is two steps that happen in order: the manifest is evaluated to a JavaScript object, then each top-level key of that object is written to a file.

## The command

```bash
npx spellcraft generate manifest.jsonnet
```

Output lands in `render/`, relative to where you run the command.

## How a filename picks its serialiser

Each key is matched against a set of regular-expression handlers, and the first match wins. SpellCraft ships three:

| Pattern | Output |
|---|---|
| `.*?\.json$` | `JSON.stringify(content, null, 4)` |
| `.*?\.yaml$` | YAML, four-space indent |
| `.*?\.yml$` | YAML, four-space indent |

Anything that matches nothing falls back to pretty-printed JSON. That fallback is why `"main.tf.json"` works without any Terraform-specific handling: Terraform reads plain JSON, and the filename already ends in `.json`.

Plugins add their own handlers through `fileTypeHandlers` in [their metadata](/docs/plugin-contract.html), which is how a plugin can teach SpellCraft to emit `.tf`, `.ini` or `.env` files.

## String values are written verbatim

If a value is a string rather than an object, the matching handler still runs — so a `.json` key holding a string produces a quoted JSON string, which is rarely what you want. For files that are genuinely text, give them an extension no handler claims:

```jsonnet
{
  "README.md": "# Generated by SpellCraft. Do not edit.\n",
}
```

## Cleaning

Before writing, SpellCraft deletes files in the render directory that match any registered handler pattern. This keeps a stale `old.tf.json` from surviving after you rename something — a real hazard when the output feeds `terraform apply`, which would happily apply the leftovers.

Two consequences worth knowing:

- Files that match no handler pattern are **not** cleaned. A `README.md` written by a previous run stays until you remove it.
- The render directory is not a place to keep anything by hand. Treat it as build output, and add it to `.gitignore` — the generators do this for you.

<div class="note plain">
<div class="label">Disabling it</div>
<p>Construct the frame with <code>cleanBeforeRender: false</code> to turn cleaning off, or point <code>renderPath</code> somewhere else entirely. See the <a href="/docs/spellframe-api.html">SpellFrame API</a>.</p>
</div>

## Rendering from code

The CLI is a thin wrapper. Anything it does, your own script can do:

```js
import { SpellFrame } from '@c6fc/spellcraft';

const frame = new SpellFrame({ renderPath: './out' });

await frame.init();
await frame.render('manifest.jsonnet');
await frame.write();
```

`render()` returns the evaluated object, so you can inspect or transform it before `write()` ever touches the disk.
